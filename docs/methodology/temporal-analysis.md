# Temporal Analysis

## Purpose

This document describes the temporal processing applied to the daily regional sea-ice coverage observations.

The temporal analysis transforms the persistent daily observations into a continuous calendar-based time series where appropriate, derives climatological statistics and anomalies, and calculates annual means.

The methodology reflects the current implementation of v0.1.

---

## 1. Input data

The temporal analysis starts from:

```text
output/analysis/ice_coverage_summary.csv
```

The file contains the daily regional observations generated by `RegionAnalyzer`.

Dates are parsed as calendar dates and the data are sorted by region and date.

---

## 2. Calendar reconstruction

For every region, the analysis constructs a complete daily calendar between the first and last available observation.

The procedure is:

```text
observed dates
      ↓
minimum / maximum date
      ↓
complete daily date range
      ↓
reindex observations
      ↓
interpolate eligible gaps
```

The calendar is constructed independently for each region.

Consequently, the temporal range of a region is determined by its own first and last available observation.

---

## 3. Interpolation

Missing values in the reconstructed calendar are interpolated using time-based linear interpolation.

The current implementation uses:

```python
interpolate(
    method="time",
    limit=14,
    limit_direction="both",
)
```

The maximum interpolation gap is therefore 14 observations/days.

The interpolation is performed on the numeric columns of the time-series data.

This currently includes the numerical area and coverage variables rather than only the final coverage metrics.

---

## 4. Interpolation limits

The interpolation is deliberately bounded.

Gaps longer than the configured limit are not bridged by the interpolation operation.

This prevents a long period without observations from being represented as a continuous sequence of estimated daily values.

The implementation also uses:

```text
limit_direction="both"
```

so missing values at the boundaries of an available series can also be filled within the configured limit.

This behavior should be considered when interpreting interpolated edge values.

---

## 5. Complete calendar years

Annual statistics are calculated only for complete calendar years.

For each region and year, the expected number of days is:

```text
365 days
```

for a non-leap year and:

```text
366 days
```

for a leap year.

A region/year is considered complete when the expected number of daily observations has a valid `relative_coverage_percent` value.

Incomplete years are excluded from the annual mean calculation.

The original time series is not modified by the complete-year filter.

---

## 6. Moving average

A centered moving average is calculated using a ±3-day window.

This corresponds to:

```text
7-day centered window
```

The smoothing is calculated separately for contiguous valid data segments.

A missing-data gap therefore does not become a connection between observations on either side of the gap.

The current rolling calculation uses:

```text
window = 7
center = True
min_periods = 1
```

Consequently, fewer than seven observations may contribute at the beginning or end of a valid segment.

The moving average is a derived smoothed series. It does not replace the underlying daily observations.

---

## 7. Climatology

The climatological reference period is:

```text
1981–2010
```

inclusive.

Climatology is calculated separately for each region and calendar day.

For each date, the implementation uses:

```text
month-day
```

rather than day-of-year.

This prevents leap years from shifting the calendar position of observations after February 29.

---

## 8. Climatological statistics

For each region and calendar day, the following statistics are calculated separately for absolute and relative coverage:

* mean,
* standard deviation,
* minimum,
* maximum.

The resulting columns include:

```text
relative_climatology_percent
relative_climatology_std_percent
relative_climatology_min_percent
relative_climatology_max_percent

absolute_climatology_percent
absolute_climatology_std_percent
absolute_climatology_min_percent
absolute_climatology_max_percent
```

The climatological mean and standard deviation provide the reference envelope used by the time-series visualizations.

---

## 9. Leap day

February 29 is treated as its own calendar day:

```text
02-29
```

when it is present in the climatological source data.

No day-of-year shifting or redistribution of February 29 is performed.

---

## 10. Anomalies

Anomalies are calculated relative to the corresponding climatological mean.

For relative coverage:

```text
relative anomaly
=
observed relative coverage
−
relative climatological mean
```

For absolute coverage:

```text
absolute anomaly
=
observed absolute coverage
−
absolute climatological mean
```

The resulting anomalies are expressed in **percentage points**.

They are not:

* relative percentage changes,
* normalized anomalies,
* standard deviations,
* z-scores.

---

## 11. Annual means

Annual means are calculated only from complete region-years.

The following quantities are averaged:

* relative coverage,
* absolute coverage,
* relative ice area,
* absolute ice area.

The resulting annual dataset contains:

```text
relative_mean_coverage_percent
absolute_mean_coverage_percent
relative_mean_ice_area_km2
absolute_mean_ice_area_km2
```

The annual dataset is sorted by region and year.

---

## 12. Trend analysis

The current `TimeSeriesAnalyzer` calculates annual means but does not calculate the linear trend or coefficient of determination itself.

Linear trend lines and corresponding R² values are calculated later by the plotting component.

This separation is intentional in the current implementation:

```text
TimeSeriesAnalyzer
    ↓
annual means
    ↓
TimeSeriesPlot
    ↓
trend line and R²
```

Therefore, trend fitting is currently part of the visualization workflow rather than the core temporal aggregation stage.

---

## 13. Persistent temporal outputs

The temporal analysis writes derived datasets including:

```text
output/analysis/ice_coverage_timeseries.csv
output/analysis/ice_coverage_yearly.csv
output/analysis/ice_coverage_events.csv
```

The original daily summary remains unchanged.

The derived time series therefore provide a reproducible intermediate representation for subsequent plotting and interpretation.

---

## 14. Interpretation of interpolated and smoothed data

Interpolated values and moving averages should be distinguished from direct observations.

### Observed values

Directly derived from the processed sea-ice concentration GeoTIFF.

### Interpolated values

Estimated from neighboring temporal observations according to the configured interpolation method and gap limit.

### Moving averages

Smoothed representations calculated from the available/interpolated time series within contiguous valid segments.

These distinctions are relevant when interpreting short-term changes or seasonal transition dates.

---

## 15. Current methodological limitations

The current implementation has several documented characteristics:

* interpolation is currently applied to all numeric columns;
* `limit_direction="both"` allows bounded edge filling;
* annual completeness is evaluated using relative coverage;
* climatology uses the fixed 1981–2010 reference period;
* trend fitting is performed by the plotting layer rather than the analyzer;
* uncertainty propagation is not currently implemented.

These characteristics are part of the v0.1 methodology and should be considered when interpreting derived results.

Systematic automated verification of these temporal transformations is planned for v0.2.
